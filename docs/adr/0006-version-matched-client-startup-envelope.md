# Version-matched client startup through the frozen invocation

The frozen client invocation in [ADR 0001](0001-version-matched-client-and-frozen-hello.md) must also support deliberate termination and carry an already validated attachment-settings snapshot. We retain `climon2-client attach --metadata <absolute path>` and select the operation through the internal, additively frozen schema-1 `CLIMON2_CLIENT_STARTUP` JSON envelope, rather than adding argv, another helper binary, or cross-version post-hello communication. The [confirmed cross-version specification in #44](https://github.com/jackgeek/climon2/issues/44) owns the exact envelope, capability gates, validation and acceptance requirements; this records the architectural choice, not a second copy of that specification.

An absent envelope preserves generic callers by selecting attach and loading the matching client's settings once; a present invalid envelope never falls back. The CLI overwrites inherited startup input and excludes it from daemon/application environments, so it is not a user configuration override. Kill mode is neither an attachment nor a terminal interaction: the matching client speaks its daemon's private protocol, while the CLI bounds the whole operation and may clean up only its own spawned helper, never signal a session PID from metadata.
